# wb-bot-model-fallback

Плагин Discourse: ответы ИИ-бота генерирует запасная, более дешёвая модель, когда пользователь
получил заданное число ответов основной моделью за сутки.

## Зачем

Основную часть расхода на бота дают единичные очень длинные диалоги: сотни ответов одному
пользователю за день. Штатные квоты Discourse AI (`LlmQuota`) тут не помогают: при превышении они
отказывают в ответе, а токены считают без кэша, то есть у модели на Responses API видят лишь малую
долю реального объёма.

## Как работает

- У каждого пользователя N ответов основной моделью за скользящие сутки (по умолчанию 20). Ответ —
  это вопрос пользователя, на который отвечал бот: в журнале `AiApiAuditLog` это разные `post_id`,
  сколько бы вызовов модели ни ушло на один ответ. Считаются личные диалоги с ботом
  (`feature_name = bot`) и ответы автоматизаций; заголовки тем, суммаризация и прочее — нет.
- Следующий вопрос переводит пользователя на запасную модель на заданный срок (по умолчанию сутки).
  Срок — ключ в Redis со временем жизни: ставится один раз и не продлевается, поэтому модель не
  прыгает туда-обратно около порога. После срока счёт начинается заново; ответы запасной модели
  в него не идут.
- Сотрудники (администраторы и модераторы) по умолчанию не ограничены.
- О переходе пользователь узнаёт из плашки в начале первого ответа облегчённой версии, о возврате —
  из плашки в начале первого ответа основной. Тексты — настройки сайта, модели в них не называются.
  Плашка дописывается тем же `revise` с `skip_revision`, которым Discourse AI сам завершает ответ:
  без пометки «изменено» и мимо истории, которую видит модель. Флаги в Redis снимаются только после
  удачного ответа, так что при сбое сообщение не теряется.
- Пока срок идёт, каждый N-й ответ облегчённой версии (по умолчанию 20) начинается с напоминания:
  отвечает облегчённая версия, основная вернётся тогда-то. Считается от ответа с сообщением о переходе,
  так что при 20 напоминания приходят в 21-м, 41-м… ответе срока. Ответы берутся из того же журнала
  (`llm_id` запасной модели с начала срока; начало — значение ключа срока), а каждое напоминание
  отмечается своим ключом с `NX`: два ответа, закончившиеся одновременно, не дадут двух напоминаний.
- Модель подменяется на один ответ в `Playground#reply_to` — общий путь личных диалогов, упоминаний
  и автоматизаций. Агент, промпт и инструменты не меняются.
- Discourse сохраняет зашифрованные рассуждения модели вместе с вызовами инструментов и отправляет их
  обратно в следующих ответах той же переписки, не привязывая к модели. Плагин на время ответа
  убирает из истории рассуждения постов, сгенерированных другой моделью (поле `ai_llm_model_id`),
  и идентификаторы их вызовов инструментов: Responses API связывает вызов `fc_…` с рассуждением того же
  ответа и без него отвергает запрос (HTTP 400). Когда отвечает запасная модель, чужим считается всё,
  что написала не она, включая старые ответы без поля модели. Посты той же модели не трогаются, так что
  без переключений поведение прежнее.
- Каждое переключение пишется в `production.log`:
  `[wb-bot-model-fallback] topic=… user=… answers=… threshold=… until_ttl=…`.

## Настройки (Админка → Настройки → Плагины)

| настройка | по умолчанию | смысл |
|---|---|---|
| `wb_bot_model_fallback_enabled` | выключено | главный выключатель |
| `wb_bot_model_fallback_daily_answers` | 20 | сколько ответов основной моделью за сутки |
| `wb_bot_model_fallback_hours` | 24 | срок на запасной модели и окно подсчёта ответов, часов |
| `wb_bot_model_fallback_exempt_staff` | включено | не ограничивать администраторов и модераторов |
| `wb_bot_model_fallback_notice_switch` | `**Вы задали помощнику %{questions} за сутки. До %{until} (МСК) на вопросы отвечает облегчённая версия помощника, потом снова основная.**` | сообщение о переходе, жирным; `%{questions}` — порог со склонённым словом, `%{answers}` — число, `%{until}` — конец срока по Москве; пусто — не показывать |
| `wb_bot_model_fallback_reminder_every` | 20 | напоминать каждые N ответов облегчённой версии; 0 — не напоминать |
| `wb_bot_model_fallback_notice_reminder` | `**Напоминаем: сейчас на вопросы отвечает облегчённая версия помощника. Основная версия вернётся %{until} (МСК).**` | текст напоминания, подстановки те же; пусто — не напоминать |
| `wb_bot_model_fallback_notice_return` | `**Снова отвечает основная версия помощника.**` | сообщение о возврате; пусто — не показывать |
| `wb_bot_model_fallback_llm` | пусто | запасная модель; пусто — плагин ничего не меняет |

## Проверка

- `spec/` — 44 примера на Discourse 2026.7.1 и 2026.8.0: счёт ответов, а не вызовов; срок на
  запасной модели и то, что он не продлевается; новый счёт после срока; исключение для сотрудников;
  отбор рассуждений и идентификаторов чужих вызовов; сообщения о переходе и возврате (по разу, со склонением, без пометки «изменено»);
  напоминания (в каких ответах срока, одно на двоих при одновременных ответах, только ответы текущего срока, 0 и пустой текст выключают);
  сквозной ответ через `Playground`. Мутации ловятся: без срока падают 4 примера, при счёте вызовов — 3,
  если сообщение о переходе не снимается — 2, без исключения для сотрудников, при счёте ответов запасной
  модели или при сообщении о возврате до конца срока — по одному; у напоминаний без `NX` — 3, без сдвига
  на ответ с сообщением о переходе — 2, без границы срока или без ветки напоминания в `Notice` — по одному.
- Сквозная проверка на тестовом портале через заглушку Responses API, без обращений к OpenAI. Заглушка
  повторяет правило OpenAI о вызовах инструментов и рассуждениях: на версии без отбора идентификаторов
  она воспроизводит отказ 400, на текущей — нет.
  3 ответа основной моделью, затем запасная на сутки, после срока снова основная; сообщения о переходе
  и возврате стоят ровно в тех ответах, где должны, и в запросы к модели не попадают; модератору всегда
  отвечает основная и сообщений нет; ни одна модель не получает рассуждений другой. Напоминания на
  стенде не прогонялись: они дописываются тем же путём, что и сообщение о переходе.

Установка на прод — строкой `git clone` в `app.yml` и перезапуском unicorn, как у других плагинов WB.
